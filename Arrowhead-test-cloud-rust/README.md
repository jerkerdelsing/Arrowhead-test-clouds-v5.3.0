# Arrowhead v5.3.0 Rust test cloud

A local Docker Compose deployment of an Eclipse Arrowhead 5.3.0 local cloud in which every core and support system is
the Rust implementation, built from the primary source tree `Eclipse-Arrowhead-rust`. It is one of three v5.3.0 test
clouds in this repository; the Java cloud is in `../Arrowhead-test-cloud-java`, the Go cloud in
`../Arrowhead-test-cloud-go`.

| | |
|---|---|
| Cloud | `RustCloud.Company.arrowhead.eu`, with its own cloud CA |
| Compose project | `arrowhead-v530-test-cloud-rust` (27 services) |
| Compose file | `compose.json`, generated by `v530/generate.py` |
| Image | `arrowhead-rust-v530/rust-systems:20261112-v530`, one image with all Arrowhead programs, built by `v530/build.sh`; RabbitMQ, Mosquitto and nginx are pinned upstream images |
| Host ports | loopback only, 64xx (see below) |
| Console | https://rustcloud-v530.localhost:6490/ |
| Federation | off: no relay, peers or peer CRLs |

`v530/README.md` is the deployment record: the deployment model, the test results, the change made to the primary
source and the known gaps.

## Model

- Each system has one JSON configuration, `config/<role>.json`, and reads its credentials from read-only files in
  `secrets/<role>/`. State is kept in bind directories under `state/`.
- Authentication seeds every identity from `bootstrapIdentities`, so provisioning never logs in as a system.
- The systems sit on an internal-only network. `edge`, an nginx TCP pass-through, is the only container that publishes
  their ports to the host.
- LocalCloudManager serves its HTTPS console itself. `console-proxy` relays to it on a separate network and admits
  only the host. The Docker socket is held only by `manager-docker-proxy`.

## Systems and ports

Every port is published on `127.0.0.1` only. A host port is the system's default port minus 2000. All system APIs
require mutual TLS with a certificate of the cloud CA.

## Prerequisites

- Docker with Compose v2, `python3`, `openssl`.
- macOS: the console password is stored in the keychain (service `arrowhead-console-arrowhead-v530-test-cloud-rust`).
- The primary Rust source checked out next to this repository, as `v530/build.sh` expects:

  ```
  <parent>/
    Eclipse-Arrowhead-rust/                             primary source
    Arrowhead-test-clouds/Arrowhead-test-cloud-rust/    this folder
  ```

- The committed `compose.json` holds absolute paths of the machine it was generated on; `make generate` rewrites it
  for the current checkout.

## What is not in git

`secrets/` (cloud CA, system certificates and keys, passwords, the console password hash) and `state/` are excluded by
`.gitignore`. A fresh clone therefore has no credentials; `v530/generate.py` creates them, and only when they are
missing. Never copy these folders between clouds or hosts.

## Deploy

```sh
make build       # v530/build.sh: the image, from the primary tree
make generate    # v530/generate.py: PKI, passwords, config/, compose.json, inventory.json, amqp/, mqtt/, edge/
make up          # v530/deploy.sh up: bootstrap order, then the local policies (v530/configure.py)
```

`make down` removes the containers and keeps credentials and state. `make ps` lists the containers.

`generate.py` rewrites `edge/*.conf`, but Compose does not recreate a container whose bind-mounted file changed. After
changing the edge configuration run `docker compose -f compose.json restart edge console-proxy`.

## Console

Open https://rustcloud-v530.localhost:6490/ and log in with the console password (`make console-password` prints it).
The console certificate is issued by the cloud CA (`secrets/ca.pem`), so the browser warns unless that CA is trusted.

## Tests

```sh
make smoke            # every system, registration, discovery, orchestration, federation off (150 checks)
make smoke-console    # logged-in console: all views and the login, Origin and Host guards (36 checks)
make smoke-security   # exposure, isolation, hardening, secrets, PKI and live revocation (141 checks)
make test             # all three
```

Results are written to `v530/*-results.json`; those of the recorded deployment (2026-11-12) are summarised in
`v530/README.md`.
